## What is Petrify?

Petrify is a self-hosted runtime for orchestrating AI agent workflows. Unlike plain DAG runners, Petrify compiles every workflow into a Petri-net and runs **static verification** (deadlock-freeness, liveness, reachability, boundedness, termination) before a single agent is invoked. The lifecycle is strict: **Plan → Verify → Execute**. Unverified workflows cannot enter execution except by explicit override.

Petrify is **import-first and model-agnostic**: it does not embed LLM inference. Blueprints arrive as JSON (pasted, imported, or generated by an external LLM). The only path for a model to participate in execution is through a pluggable **AgentAdapter**.

## Why Petrify?

The AI agent space is already crowded with excellent tools — Claude Code, Codex, Cursor, OpenClaw, Hermes, and many others. There is no point competing with them. Each of these tools has its own strengths, its own skill ecosystem, MCP servers, and plugins. Petrify does not try to replace any of them. Instead, it asks a different question: **what if you could orchestrate all of them together?**

Petrify sits one level above individual agents. You bring your own favorite tools; Petrify schedules, connects, and verifies the workflow between them. Your existing skills, MCP integrations, and plugins keep working — Petrify just coordinates when and how each tool runs.

**The origin story.** This project started with a personal itch: I wanted to use AI to write a novel. Specifically, I wanted to generate multiple chapters in parallel and then merge them into a coherent whole. The naive approach — prompt one agent, wait, prompt the next — was painfully slow. I wanted true concurrency. But as I thought about it more, I realized the problem was not about writing novels at all. It was about being locked into a single agent. Why should a complex creative task be bottlenecked through one tool?

The emergence of the **ACP (Agent Communication Protocol)** made a better answer possible. With a standard communication layer, Petrify can dispatch work to multiple heterogeneous agents simultaneously — a writing agent here, a critique agent there, and in the future, perhaps an image-generation model or a video synthesis tool, all participating in the same workflow as first-class nodes.

**A note on authorship.** My own coding ability is fairly average. The current version of Petrify was written almost entirely by Claude Code; I contributed the ideas, the architecture decisions, and the product thinking. I mention this not as a disclaimer, but because it is itself a demonstration of what this project is about: AI tools are already powerful enough that the bottleneck is no longer writing code — it is knowing what to build.

## Key Features

- **Formal verification** — Petri-net static analysis catches deadlocks, livelocks, and unbounded loops before runtime
- **Plan → Verify → Execute lifecycle** — enforced gate between authoring and execution
- **Pluggable adapters** — ACP (Agent Communication Protocol), Mock (testing), and extensible to `claude-code-cli`, `openai-tools`, or any custom adapter
- **Checkpoint / Resume / Time Travel** — save and restore workflow state at any node boundary; scrub through execution history
- **Workflow IDE** — React Flow–based editor with node panels, event stream viewer, and breakpoint debugger
- **Bilingual example blueprints** — four ready-to-import workflow examples in both English and Chinese

## Getting Started

### Prerequisites

- Node.js 20 or later
- npm 10 or later

### Install

```bash
git clone https://github.com/<your-org>/petrify.git
cd petrify
npm install
```

### Run (development)

```bash
npm run dev
```

- Backend: `http://localhost:4000`
- Frontend: `http://localhost:5173`

### Run (production build)

```bash
npm run build
npm --workspace @petrify/server start
```

---

## Quick Start

1. Open `http://localhost:5173` in your browser.
2. Click **New Project**, then **Import Blueprint**.
3. Paste the contents of any file from the `examples/` directory (e.g. `blog-post-pipeline-en.json`).
4. Click **Verify** to run the Petri-net analysis.
5. Connect an adapter (Settings → Adapters), then click **Run**.

### ACP Adapter

Set the environment variable `PETRIFY_ACP_CMD` to the command that spawns your ACP-compatible agent (e.g. `opencode`):

```bash
PETRIFY_ACP_CMD=opencode npm run dev
```
